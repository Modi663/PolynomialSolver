# Настройки бисекции, живой график и история решений

Дата: 2026-10-29. Статус: согласовано; уточнения пользователя включены.

## Задача

Упростить главное окно PolynomialSolver, дать возможность менять уравнение без очистки результата, сравнивать методы и сохранять последовательность расчётов в виде консоли. График должен обновляться при изменении коэффициентов, а ошибки ввода — подчёркивать неверные поля красным и показываться под ними.

Пользователь уточнил: отдельное окно требуется для **настроек бисекции**, в главном окне нужна кнопка их открытия. Выбран обычный диалог с кнопкой **«Применить»**.

## Подходы

1. **Диалог с применением настроек — выбран пользователем.** Можно заполнить и проверить обязательные поля, затем применить согласованный набор параметров. Закрытие или отмена сохраняют ранее применённые значения.
2. Немодальное окно с мгновенным применением. Уменьшает число нажатий, но незавершённые границы сразу меняют состояние расчёта и требуют дополнительной синхронизации. Не выбрано.

Сохраняем C++20, Qt Widgets, Qt Charts и существующую форму Qt Designer. Новые библиотеки не нужны.

## Главное окно

- Сохраняются выбор степени 1–5, коэффициенты, журнал результатов и график.
- Выбор метода: «Аналитический», «Бисекция», «Оба метода». Для степеней 4–5 доступна только бисекция; аналитические решатели в проекте существуют для степеней 1–3.
- Кнопка «Настройки бисекции» доступна при выборе бисекции или обоих методов.
- Кнопка «Решить» запускает расчёт; Enter имеет то же действие. Если обязательные параметры бисекции ещё не применены, открывается диалог настроек. После их применения пользователь снова запускает расчёт.
- Решение не блокирует поля. Изменение степени или коэффициентов не удаляет журнал.
- Отдельная кнопка «Очистить историю» удаляет записи, но сохраняет уравнение и настройки.
- Отдельная кнопка построения графика не нужна: выбрано предложенное пользователем автоматическое обновление.

## Диалог настроек бисекции

- Левая и правая границы изначально **пустые**, обе обязательны. Допускаются точка, запятая и научная запись. Значения должны быть конечными; левая граница строго меньше правой.
- Точность задаётся существующим количеством знаков после запятой 0–15, по умолчанию 6. Подпись явно объясняет единицу точности.
- Флажок «Найти все корни» объединяет выбор одного/нескольких корней; дополнительный дублирующий переключатель не нужен. По умолчанию флажок выключен — это предложение исполнителя.
- При выключенном флажке шаг скрыт и не участвует в проверке или вычислениях. Бисекция применяется непосредственно ко всему заданному интервалу и возвращает один корень. Корень на границе принимается. Если на границах одинаковые ненулевые знаки, выводится объяснение, что нужен интервал со сменой знака; это не утверждение об отсутствии корней внутри.
- При включённом флажке показывается положительный шаг сканирования, по умолчанию 0.25. Интервал обходится с этим шагом, найденные участки со сменой знака уточняются бисекцией. Корни на узлах и обеих границах учитываются.
- Возле режима поиска всех корней видна короткая подсказка: сканирование может пропускать кратные корни между узлами и несколько корней внутри одного шага. Название режима не означает математической гарантии полноты.
- Слишком большое число шагов отклоняется до запуска: максимум 100 000 участков, чтобы не блокировать интерфейс длительным обходом. Шаг, не сдвигающий число в double, также отклоняется.
- «Применить» проверяет все активные поля. При ошибке диалог остаётся открытым; неверные поля подчёркнуты красным, под полями показано объяснение. При успехе настройки сохраняются на время работы приложения и диалог закрывается.
- При редактировании ошибочного поля проверка обновляется без перехвата фокуса и выделения текста. Неактивный скрытый шаг не вызывает ошибок.

## Автоматический график и проверка коэффициентов

- График строится по коэффициентам независимо от запуска решателей и заполнения настроек бисекции. Поэтому пустые обязательные границы не мешают предварительному просмотру полинома.
- После изменения коэффициентов или степени ввод проверяется сразу. Кривая обновляется плавной анимацией существующих серий, без удаления и создания графика при каждом изменении. Переход длится около 200 мс, повторный ввод перенаправляет текущий переход к новым данным.
- Нечисловые, пустые и бесконечные значения недопустимы; старший коэффициент не может быть нулём. Все неверные поля получают красное подчёркивание, под формулой выводится сообщение. Исправление убирает подсветку автоматически.
- При некорректных коэффициентах график очищается, чтобы не показывать кривую предыдущего уравнения как текущую. Фокус остаётся у пользователя.
- При корректном изменении коэффициентов прежние маркеры корней исчезают. После нового решения отмечаются найденные вещественные корни текущего уравнения.
- Сохраняются масштабирование, перемещение и «Сбросить вид». Сброс доступен всегда, когда есть корректный график. При вводе нового полинома вид подбирается заново.
- При вводе ошибки показываются только подчёркиванием и текстом под полями. При нажатии «Решить» с ошибочными данными дополнительно показывается QMessageBox. Ошибки вычисления по явному запуску также показываются в сообщении; журнал прошлых успешных расчётов сохраняется.

## История и сравнение

- Журнал только для чтения, с моноширинным шрифтом и возможностью выделить и скопировать текст.
- Каждый запуск добавляет запись: номер расчёта, уравнение, метод, параметры бисекции при её использовании, корни и невязки |P(x)|. Последняя запись выделяется фоном; при новом расчёте выделение предыдущей снимается.
- В режиме «Оба метода» два результата находятся в одной записи. У каждого метода собственные заголовок, корни и невязки. Если один метод завершился ошибкой, успешный результат другого сохраняется, а ошибка подписана своим методом.
- Аналитический метод показывает все свои корни, включая комплексные и кратности. Бисекция показывает вещественные корни заданного интервала согласно выбранному режиму. Эта разница явно указана в записи сравнения.
- При отсутствии найденных корней в режиме сканирования сообщение относится к заданным интервалу и шагу. В режиме одного корня несоблюдение условия смены знака — отдельная ошибка.
- Под сохранением понимается история текущего сеанса. Запись в файл и восстановление после перезапуска в эту правку не входят; это граница объёма, предложенная исполнителем.

## Изменения в проекте

- Новый BisectionSettingsDialog хранит и проверяет настройки отдельно от MainWindow. Применённые значения и черновик диалога разделены.
- В BisectionSolver и PolynomialSolverService добавляется явный путь для одного корня без сканирования. Существующий путь сканирования сохраняется и получает ограничение числа участков.
- MainWindow больше не использует состояние блокировки после решения. Отдельные операции отвечают за валидацию, предварительный график, запуск методов и добавление записи в журнал.
- PolynomialChartView меняет приглашение пустого графика: оно больше не требует предварительно решить уравнение.
- README и тесты обновляются под новое поведение.

## Проверка результата

Математические тесты: один корень без шага, обе границы, одинаковые знаки, точность, включение обоих краёв при сканировании, ограничение числа участков и невозможность продвижения в double.

UI-тесты: пустые обязательные границы, применение и отмена настроек, шаг только для поиска всех корней, ввод с запятой, живой график и его очистка при ошибке, исправление подсветки без потери фокуса, редактирование после решения, накопление истории и выделение последней записи, запуск обоих методов и ограничение степеней 4–5.

После реализации: сборка Debug и Release, соответствующие тестовые наборы, визуальная проверка главного окна и диалога.

Исходная проверка: Debug собран из текущих исходников; все 10 существующих тестовых наборов проходят.
